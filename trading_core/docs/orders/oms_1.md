**OMS (Order Management System)** — это система управления торговыми заявками (ордерами) в финансовой торговой инфраструктуре.

В контексте FinTech, HFT и Trading OMS отвечает за полный жизненный цикл ордера: от момента его создания до исполнения, отмены или отклонения.

## 1. Основные задачи OMS

Типичный OMS выполняет следующие функции:

| Функция | Описание |
|---|---|
| Order Creation | Создание новых ордеров |
| Order Validation | Проверка корректности ордера |
| Order Routing | Маршрутизация ордеров на биржи или брокерам |
| Order Tracking | Отслеживание состояния ордеров |
| Order Modification | Изменение параметров существующего ордера |
| Order Cancellation | Отмена ордеров |
| Execution Management | Обработка информации об исполнении |
| Risk Checks | Проверка торговых ограничений |
| Position Tracking | Учёт текущих позиций |

## 2. Жизненный цикл ордера (Order Lifecycle)

Рассмотрим типичный сценарий.

Допустим, торговая стратегия хочет купить 10 BTC по цене $100 000.

Она отправляет в OMS заявку:

```cpp
struct Order
{
    std::uint64_t orderId;
    std::string symbol;

    Side side;
    OrderType type;

    std::uint64_t price;
    std::uint64_t quantity;

    OrderStatus status;
};
```

Далее происходит примерно следующее:

```text
Trading Strategy
       |
       v
      OMS
       |
       v
  Risk Validation
       |
       v
  Order Routing
       |
       v
    Exchange
       |
       v
  Order Execution
       |
       v
  Execution Report
       |
       v
      OMS
       |
       v
 Trading Strategy
```

Основные состояния ордера:

```cpp
enum class OrderStatus
{
    New,
    PendingNew,
    PartiallyFilled,
    Filled,
    PendingCancel,
    Canceled,
    Rejected,
    Expired
};
```

Например:

1. Strategy отправляет ордер.
2. OMS принимает его.
3. OMS проверяет ограничения.
4. Ордер отправляется на биржу.
5. Биржа подтверждает регистрацию ордера.
6. Приходит частичное исполнение (Partial Fill).
7. Приходит ещё одно исполнение.
8. Ордер переходит в состояние Filled.

Важно: OMS должен корректно обрабатывать асинхронные события, включая частичные исполнения, отклонения, отмены и повторные сообщения.

## 3. OMS vs EMS

В торговой инфраструктуре часто встречаются два похожих понятия:

- **OMS (Order Management System)** — управление жизненным циклом ордеров.
- **EMS (Execution Management System)** — управление процессом исполнения ордеров.

Условно:

| OMS | EMS |
|---|---|
| Управляет ордерами | Оптимизирует исполнение |
| Контролирует состояние ордеров | Выбирает стратегии исполнения |
| Отслеживает позиции | Выбирает биржи и маршруты |
| Управляет отменами и изменениями | Выполняет Smart Order Routing |
| Обеспечивает целостность торговых операций | Минимизирует slippage и market impact |

На практике граница между ними не всегда чёткая. Многие современные системы объединяют OMS и EMS.

## 4. OMS в контексте HFT

В HFT инфраструктуре OMS может быть существенно проще по функциональности, но гораздо требовательнее к производительности.

Типичная архитектура:

```text
             Trading Strategies
                     |
                     v
              +-------------+
              |     OMS     |
              +-------------+
                     |
             +---------------+
             | Risk Manager  |
             +---------------+
                     |
             +---------------+
             | Order Router  |
             +---------------+
                     |
          +----------+----------+
          |          |          |
          v          v          v
       Binance    CME       NASDAQ
       Connector  Connector  Connector
          |          |          |
          v          v          v
       Exchange  Exchange   Exchange
```

Основные технические требования:

- Low latency — минимальная задержка обработки ордера.
- Lock-free / Wait-free structures — минимизация синхронизации.
- Memory pre-allocation — минимизация динамических аллокаций.
- Deterministic latency — предсказуемое время обработки.
- High throughput — обработка большого количества сообщений.
- Reliable state management — согласованность состояния ордеров.
- Recovery — восстановление состояния после сбоев.

Особенно важна обработка сообщений от биржи: New Ack, Execution Report, Cancel Ack, Reject и т. д.

Для этого часто используется FIX Protocol, хотя современные биржи также предоставляют собственные бинарные протоколы.

## 5. OMS и OrderBook — в чём разница?

Это два совершенно разных компонента торговой инфраструктуры.

| OrderBook | OMS |
|---|---|
| Хранит bids и asks | Управляет собственными ордерами |
| Отображает состояние рынка | Отображает состояние торговых заявок |
| Обрабатывает Market Data | Обрабатывает Order Events |
| Содержит уровни цен и объёмов | Содержит ордера и их состояния |
| Обычно строится из market data | Строится на основе торговых операций и подтверждений биржи |

Например:

- Market Data Connector получает изменения OrderBook с Binance.
- Trading Strategy анализирует рынок.
- OMS принимает решение стратегии в виде нового ордера.
- Order Router отправляет ордер через Binance Trading Connector.
- OMS получает Execution Report и обновляет состояние ордера.

### 6. Какие компоненты стоит знать C++ разработчику в HFT

Я бы выделил следующую последовательность изучения:

1. **Order Management System (OMS)** — управление ордерами.
2. **Execution Management System (EMS)** — управление исполнением.
3. **Risk Management System (RMS)** — контроль торговых рисков.
4. **Order Router** — маршрутизация ордеров.
5. **Exchange Connectivity** — взаимодействие с биржами.
6. **Position Management** — управление позициями.
7. **Pre-trade Risk Checks** — проверки перед отправкой ордера.
8. **Drop Copy** — получение независимой копии торговых сообщений для контроля и сверки.

Особенно рекомендую разобраться в связке **OMS + Exchange Connectivity + Order Lifecycle + FIX Protocol**.

Это фундаментальная часть инфраструктуры практически любой профессиональной торговой системы.
